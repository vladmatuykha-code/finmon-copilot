# FinMon Copilot

Мультиагентний помічник аналітика фінансового моніторингу банку. Система моніторингу знаходить підозрілу активність клієнта, а три агенти на LangGraph розбирають її як аналітик: збирають факти через інструменти, знаходять відповідні статті Закону №361-IX і пункти Положення НБУ №65 і пропонують рішення — ескалювати, запросити документи чи закрити як хибне спрацювання.

**Стек:** Python · LangGraph · Anthropic Claude API (Opus 5.5, Sonnet 5.5, Haiku 5.5) · Google Gemini API (3.8 Flash, 3.5 Flash Lite) · tool use · structured outputs · RAG (Qdrant + fastembed + BM25, гібридний пошук) · PyTorch · Hugging Face Transformers · PEFT (LoRA) · scikit-learn · FastAPI · Prometheus · GitHub Actions · Docker · pytest

> Дані клієнтів і транзакцій синтетичні: їх згенеровано за індикаторами підозрілості з Додатка 20 до Положення НБУ №65. Нормативні документи справжні: Закон 361-IX у редакції від 23.10.2026 і Положення НБУ №65 з офіційного сайту Верховної Ради.

## Що всередині

```
спрацювання → load_context → triage → investigator ⇄ 8 інструментів → verify → reviewer → звіт
                                           ▲                                    │
                                           └────── revise (до 1 разу) ──────────┘
```

- **triage** — гіпотези (і схеми, і легальні пояснення) та план перевірки;
- **investigator** — цикл ReAct з 8 інструментами: анкета KYC, транзакції, показники рахунку, контрагенти, санкційні переліки, сесії онлайн-банкінгу, банкомати, пошук по нормативці;
- **verify** — код без LLM: кожна транзакція в доказах існує і належить клієнту, кожне посилання на закон агент справді отримав із пошуку;
- **reviewer** — другий агент перевіряє висновок і може повернути на доопрацювання;
- у фінальний звіт потрапляють лише перевірені посилання.

Навколо графа:
- **два провайдери моделей** — Claude і Gemini через один інтерфейс; якщо провайдер недоступний після повторів, виклик автоматично переходить на іншого, і розслідування продовжується з того самого кроку;
- **моніторинг** — метрики Prometheus (`/metrics`), сторінка стану (`/monitor`), JSON-логи, 6 правил алертів з тестами;
- **CI** — GitHub Actions на кожен push: тести, якість пошуку з порогом, правила алертів; прогін агентів з порогами якості — вручну;
- **NLP-класифікатор призначень платежів** — XLM-RoBERTa, дотренована на PyTorch з LoRA, у порівнянні з ключовими словами, TF-IDF і LLM.

Докладно: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Результати

### Рішення агентів на 40 і 200 спрацюваннях

18 справжніх схем (дроблення готівки нижче порогу, «дропи», транзитні компанії, чужий онлайн-банкінг, нелегальні азартні ігри, санкційний збіг, публічний діяч з непоясненими доходами, погашення кредиту третіми особами, кластер зняття в банкоматі), 16 хибних спрацювань і 6 спірних випадків.

### Головне

- **Маршрутизація моделей:** Haiku збирає факти, Sonnet перевіряє — якість як Opus, але в 7 разів дешевше ($0.035 за розбір).
- **200 спрацювань:** усі 90 справжніх схем знайдено, 0 хибних ескалацій; слабке місце — спірні випадки «запросити документи» (57%), на 40 кейсах його не було видно.
- **Аналіз помилок → промпт v2:** точність Haiku 57.5% → 90%, усі помилки v1 були однакові («запросити документи» замість рішення).
- **Два провайдери:** Gemini 3.8 Flash — 100% на 40 кейсах за $0.048; дешевий Gemini 3.5 Flash Lite пропускає санкційні збіги. Якщо провайдер падає, розбір продовжується на іншому з того самого кроку.
- **Пошук:** короткий заголовок-контекст і гібрид підняли Recall@5 з 53% до 83% на MiniLM і до 93% на multilingual-e5-large.
- **NLP:** XLM-RoBERTa з LoRA (0.43% параметрів) класифікує призначення платежів на 87% проти 48% у ключових слів; каскад з Claude Haiku — 95.9%.
- **ML-бейзлайн** ламається на нових схемах (70–75%), агент — ні.

Повний розбір і обмеження: [docs/RESULTS.md](docs/RESULTS.md).

## Запуск

```bash
uv venv --python 3.12 .venv && source .venv/bin/activate
uv pip install -e ".[dev]"
cp .env.example .env                        # ANTHROPIC_API_KEY, GEMINI_API_KEY
python -m finmon.data_gen                   # 40 спрацювань для оцінки
python -m finmon.data_gen --large           # 200 спрацювань для масштабної оцінки
python -m finmon.data_gen --train           # 240 для ML-бейзлайну
python -m finmon.rag.index minilm structural_short
python cli.py A010 --config haiku           # один розбір у терміналі
uvicorn finmon.api:app --reload             # демо на :8000, моніторинг /monitor, метрики /metrics
python -m pytest -q tests                   # тести без звернень до API
python -m evals.run_retrieval_eval          # оцінка пошуку
python -m evals.run_baseline                # ML-бейзлайн
python -m evals.run_agent_eval haiku routed sonnet opus gemini gemini_lite
python -m evals.run_agent_eval routed --dataset eval_large
python -m evals.gate agent routed           # пороги якості, код 1 якщо гірше
FINMON_CHAOS=anthropic python cli.py A011 --config routed   # імітація збою Anthropic

uv pip install -e ".[nlp]"                  # PyTorch, Transformers, PEFT
python -m evals.gen_purpose_data            # дані для класифікатора призначень
python -m evals.run_purpose_clf             # ключові слова, TF-IDF, XLM-R, LoRA, Haiku
python -m evals.run_purpose_cascade         # каскад LoRA → Haiku
```

Або `docker compose up --build` — сервіс разом з Prometheus і правилами алертів.

## Структура

```
finmon/
  config.py          моделі, ціни, конфігурації агентів, резервні провайдери
  llm.py             Claude і Gemini через один інтерфейс: вартість, кеш, повтори, резерв
  obs.py             метрики Prometheus, JSON-логи, підсумок для /monitor
  data_gen.py        генератор синтетичного банку і спрацювань
  store.py           доступ до даних і 20+ ознак рахунку
  tools.py           8 інструментів зі strict-схемами
  rag/chunking.py    нарізка нормативки (3 стратегії)
  rag/index.py       Qdrant + BM25 + RRF
  agents/            граф LangGraph, промпти, Pydantic-схеми
  nlp/purposes.py    категорії призначень платежів, ключові слова, класифікатор з LoRA
  api.py             FastAPI: демо, /monitor, /metrics
evals/               оцінка агентів, пошуку, ML-бейзлайну і класифікатора; пороги якості
deploy/prometheus/   конфігурація Prometheus, правила алертів і їх тести
.github/workflows/   CI
tests/               тести графа, резервного провайдера і перекладу історії між провайдерами
docs/                архітектура, результати, розбір проєкту російською
```
